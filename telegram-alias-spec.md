# Техническое задание: Telegram Mini App «Alias»

## 1. Цель проекта

Разработать Telegram Mini App для игры в Alias компанией с одного устройства.

Приложение должно быть визуально современным, быстрым, плавным и оптимизированным именно под Telegram Mini Apps.

Ключевые особенности:

- Telegram Mini App;
- React + TypeScript;
- backend на FastAPI;
- адаптация под Telegram Light / Dark Theme;
- несколько команд;
- кастомные названия команд;
- красивые свайпы карточек влево / вправо;
- пользовательские словари;
- загрузка словарей файлами с устройства;
- поддержка `.txt` и `.csv`;
- подсказки для отдельных слов;
- сложность слов от 1 до 3;
- гендерная принадлежность слов;
- специальный режим «мальчики против девочек»;
- все загруженные словари доступны всем пользователям;
- данные хранятся на сервере без отдельной БД;
- серверное JSON-хранилище;
- плавные анимации и Telegram Haptic Feedback;
- локальный игровой цикл без задержек на сеть.

---

## 2. Основной стек

### Frontend

- React;
- TypeScript;
- Vite;
- React Router;
- Zustand или Redux Toolkit;
- Framer Motion / Motion for React;
- Telegram Mini Apps API;
- CSS Modules или Tailwind CSS.

Рекомендуемый стек:

```text
React
TypeScript
Vite
React Router
Zustand
Framer Motion
Telegram Mini Apps API
```

### Backend

- Python;
- FastAPI;
- Pydantic;
- Uvicorn.

### Хранение данных

Отдельную СУБД не использовать.

Данные хранить в JSON-файлах на сервере.

Пример:

```text
data/
  dictionaries/
    index.json
    <dictionary-id>.json

  games/
    <game-id>.json

  users/
    <telegram-user-id>.json

  settings/
    global.json
```

Для MVP этого достаточно.

При этом запись JSON должна быть:

- атомарной;
- безопасной при параллельных запросах;
- с временным файлом и последующим rename;
- с блокировкой записи;
- без возможности получить битый JSON при падении процесса во время сохранения.

## 3. Общая архитектура

Приложение состоит из:

```text
Telegram
   ↓
Telegram Mini App
   ↓
React frontend
   ↓
FastAPI
   ↓
JSON files on server
```

Игровой процесс должен работать local-first.

То есть:

```text
свайп карточки
↓
изменение состояния frontend
↓
мгновенное отображение новой карточки
```

Не делать сетевой запрос после каждого свайпа.

Результаты можно синхронизировать:

- после завершения раунда;
- при завершении игры;
- при явном сохранении настроек.

---

## 4. Telegram-интеграция

При запуске:

1. вызвать Telegram Mini Apps API;
2. получить `initData`;
3. отправить `initData` на backend;
4. backend валидирует подпись;
5. frontend получает авторизованную сессию;
6. вызывается `Telegram.WebApp.ready()`;
7. вызывается `Telegram.WebApp.expand()`.

Никаких:

- логинов;
- паролей;
- регистрации;
- email.

# СЛОВАРИ

## 11. Общий принцип

Словари не являются приватными.

Все словари, загруженные через приложение, становятся доступны всем пользователям Telegram Mini App.

То есть используется единая серверная библиотека словарей.

Можно хранить:

- автора загрузки;
- дату создания;
- дату изменения;

но права чтения публичные для всех пользователей.

## 14. TXT-формат

TXT — самый простой формат.

Каждая непустая строка является отдельным словом или фразой.

Пример:

```text
капибара
Minecraft
кринж
маркетплейс
пельмени
работа из дома
```

Правила:

- одна строка = одно слово / фраза;
- trim пробелов;
- поддержать `\n`;
- поддержать `\r\n`;
- удалить BOM;
- удалить пустые строки;
- удалить дубликаты case-insensitive.

TXT-слова импортируются с метаданными по умолчанию:

```json
{
  "difficulty": 1,
  "hint": null,
  "gender": "neutral"
}
```

# CSV-ФОРМАТ

## 15. Общая структура CSV

CSV содержит данные о словах.

Фиксированный порядок столбцов:

```text
1. word
2. difficulty
3. reserved
4. hint
5. gender
```

Третий столбец сейчас не используется.

Он резервируется для будущего расширения и при импорте игнорируется.

То есть формат:

```csv
word,difficulty,reserved,hint,gender
```

Пример:

```csv
дрель,1,,инструмент для сверления,male
помада,1,,косметика для губ,female
карбюратор,3,,часть двигателя,male
тушь,2,,используется для ресниц,female
капибара,1,,крупный грызун,neutral
```

---

## 16. CSV без заголовка

Поддержать CSV и без header.

Пример:

```csv
дрель,1,,инструмент для сверления,male
помада,1,,косметика для губ,female
```

Если первая строка содержит:

```text
word
difficulty
hint
gender
```

считать её заголовком.

Иначе считать первой записью.

---

## 17. CSV-поля

### 1. `word`

Обязательное.

Тип:

```text
string
```

Ограничение:

```text
1–100 символов
```

---

### 2. `difficulty`

Обязательное или со значением по умолчанию.

Допустимые значения:

```text
1
2
3
```

Где:

```text
1 = лёгкое
2 = среднее
3 = сложное
```

Если значение отсутствует:

```text
difficulty = 1
```

Если значение не входит в диапазон:

строка должна отображаться в preview как ошибочная.

---

### 3. `reserved`

Пока не используется.

Может быть:

- пустым;
- содержать произвольный текст.

Backend должен сохранить совместимость формата, но не использовать это значение в игровой логике.

---

### 4. `hint`

Необязательная подсказка.

Тип:

```text
string | null
```

Пример:

```text
инструмент для сверления
```

Ограничение:

```text
до 200 символов
```

---

### 5. `gender`

Гендерная принадлежность слова.

Допустимые значения:

```text
male
female
neutral
```

Также при импорте разрешить русские варианты:

```text
м
муж
мужской

ж
жен
женский

н
neutral
нейтральный
```

После импорта backend нормализует всё к:

```text
male
female
neutral
```

Если поле пустое:

```text
neutral
```

## 20. Нормализация

Во время импорта:

- trim;
- удалить BOM;
- пропускать пустые строки;
- нормализовать line endings;
- дубликаты определять case-insensitive;
- оригинальный регистр первого экземпляра сохранять.

Пример:

```text
Telegram
telegram
 TELEGRAM
```

→

```text
Telegram
```

---

## 21. Duplicate policy

Дубликат определяется внутри конкретного словаря.

Ключ:

```text
normalizedWord
```

Пример:

```ts
normalizedWord = word
  .trim()
  .toLocaleLowerCase('ru-RU')
```

## 23. JSON-хранение словарей

Каждый словарь хранить отдельным JSON.

Пример:

```text
data/dictionaries/83be28fc.json
```

Содержимое:

```json
{
  "id": "83be28fc",
  "title": "Наши приколы",
  "description": "",
  "createdByTelegramUserId": "123456789",
  "source": "upload",
  "createdAt": "2026-09-17T10:00:00Z",
  "updatedAt": "2026-09-17T10:00:00Z",
  "words": [
    {
      "id": "word-1",
      "word": "Дрель",
      "normalizedWord": "дрель",
      "difficulty": 1,
      "hint": "Инструмент для сверления",
      "gender": "male"
    }
  ]
}
```

Отдельно хранить лёгкий индекс:

```text
data/dictionaries/index.json
```

В index хранить только metadata:

```json
[
  {
    "id": "83be28fc",
    "title": "Наши приколы",
    "wordsCount": 482,
    "createdAt": "...",
    "updatedAt": "..."
  }
]
```

Не читать все десятки тысяч слов для отображения списка словарей.

## 25. Классический режим

Все команды получают слова:

```text
male
female
neutral
```

в зависимости только от:

- выбранного словаря;
- выбранной сложности;
- отсутствия повторений.

---

## 26. Режим «Мальчики против девочек»

Это отдельный режим игры.

В нём создаются две стороны:

```text
Мальчики
Девочки
```

Название каждой команды можно изменить.

Например:

```text
Мальчики → Джентльмены
Девочки → Богини
```

При этом каждой стороне сохраняется внутренний тип:

```ts
'maleTeam'
'femaleTeam'
```

---

## 27. Логика гендерного режима

Команда мальчиков получает:

```text
gender = female
```

Команда девочек получает:

```text
gender = male
```

То есть:

```text
Мальчики объясняют женские слова.
Девочки объясняют мужские слова.
```

Слова:

```text
gender = neutral
```

в этом режиме по умолчанию не используются.

Добавить настройку:

```text
[ ] Добавлять нейтральные слова
```

Если включена:

- neutral добавляются обеим сторонам.

---

## 28. Проверка доступности слов

Перед стартом гендерного режима проверить словарь.

Например:

```text
female words >= minimum
male words >= minimum
```

Если слов одного типа слишком мало:

```text
В выбранном словаре недостаточно женских слов.

Женских: 12
Минимум: 20
```

Не позволять начать игру с заведомо пустой колодой.

# JSON STORAGE

## 64. Атомарная запись

Нельзя делать:

```python
open(path, "w")
```

и напрямую переписывать основной JSON.

Алгоритм:

```text
1. сформировать новый JSON
2. записать во временный файл
3. flush
4. fsync
5. atomic rename
```

---

## 65. Locking

При записи использовать блокировку.

Например:

```text
per-file async lock
```

или файловый lock.

Нужно предотвратить две одновременные записи одного словаря.

---

## 66. Ограничения JSON-архитектуры

Решение рассчитано на небольшой / средний party-app.

Не делать один огромный:

```text
database.json
```

с тысячами словарей внутри.

Использовать:

```text
1 dictionary = 1 JSON file
```

Это уменьшает:

- lock contention;
- размер каждой записи;
- риск повреждения;
- расход памяти.

# ACCEPTANCE CRITERIA

## 79. Базовый сценарий

Пользователь:

1. открывает Telegram Mini App;
2. приложение использует тему Telegram;
3. выбирает `Новая игра`;
4. выбирает классический режим;
5. создаёт 3 команды;
6. задаёт названия;
7. выбирает словарь;
8. выбирает сложности 1 и 2;
9. запускает игру;
10. получает карточки;
11. свайп вправо засчитывает слово;
12. свайп влево пропускает;
13. подсказка раскрывается;
14. таймер завершает раунд;
15. отображаются результаты;
16. ход переходит следующей команде;
17. определяется победитель;
18. можно начать реванш.

---

## 80. Import acceptance criteria

Пользователь:

1. открывает `Словари`;
2. нажимает `Загрузить словарь`;
3. Telegram Mini App открывает picker файла устройства;
4. пользователь выбирает `.txt`;
5. приложение показывает preview;
6. пользователь подтверждает;
7. словарь сохраняется на сервере;
8. словарь появляется в общем списке;
9. другой пользователь тоже видит этот словарь;
10. словарь можно выбрать в новой игре.

---

## 81. CSV acceptance criteria

Пользователь загружает:

```csv
дрель,1,,инструмент для сверления,male
помада,1,,косметика для губ,female
карбюратор,3,,часть двигателя,male
тушь,2,,используется для ресниц,female
```

После импорта:

- `word` сохранён;
- `difficulty` сохранён;
- третий столбец игнорируется;
- `hint` сохранён;
- `gender` нормализован;
- слова доступны в игре.

---

## 82. Gender Battle acceptance criteria

Пользователь:

1. создаёт игру;
2. выбирает `Мальчики против девочек`;
3. выбирает словарь;
4. начинается ход команды мальчиков;
5. им выдаются только слова `female`;
6. начинается ход команды девочек;
7. им выдаются только слова `male`;
8. neutral не появляется, если соответствующая настройка выключена;
9. score работает как в обычной игре.
